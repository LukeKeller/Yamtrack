Yamtrack — Feature Gap Analysis

A deep-dive into flows and features that feel missing from the current build, grounded in a full codebase inventory and fresh research across ~30 competing media-tracking tools. Every item below was checked against both the shipped code and the existing IDEAS.md backlog so the list is genuinely new.

§ Executive summary

Yamtrack is already a remarkably complete tracker — far ahead of its own docs. It has vinyl/music tracking with ListenBrainz scrobbling, an OPDS ebook library with KOReader two-way sync, Hardcover sync, a taste-profile recommender, a browse/discovery surface with "not interested" dismissals, a Spotify-style Wrapped, streak stats, and a dense home page (Up Next, Watch Tonight, On This Day, Palate Cleanser, Stale Planning). That maturity means the remaining gaps are not "add basic tracking" — they're depth-of-logging, decision-support, and availability-intelligence features that power-users of the best single-purpose trackers reach for daily.

The strongest recurring theme across competitors: Yamtrack is excellent at recording state ("I am 40% through this") but thin on recording events over time ("I read this on these three dates, audiobook, 4 stars, no spoilers"). A first-class diary / relog model (gap 1) is the single highest-leverage foundation — it unlocks per-episode ratings, rewatch-aware Wrapped, format tracking, and play journals. The other two high-impact clusters are "decide what to watch next" tooling (roulette, time-budget, backlog analyzer) and streaming availability alerts (the app already stores your services and region but never tells you when a watchlist title lands on — or leaves — them).

How to read this: each card states the gap, the evidence it's actually absent (with file references), the competitor that inspired it, a concrete implementation sketch tied to real models/views, a rough effort, and an explicit note on how it differs from anything already in IDEAS.md.

A Logging & journaling depth record events, not just state

The biggest conceptual gap. Yamtrack stores one row of current tracking state per (user, item). Repeats/rewatches are derived from the simple_history audit trail rather than logged as intentional, dated, ratable events — so there is no diary, no per-episode rating, and no way to say "I watched this twice, loved it the first time."

A1 First-class Diary & relog model High impact

A dedicated LogEntry (date, optional rating, optional note, format, rewatch flag) so the same film/book/game can be logged multiple times as distinct dated entries, plus a chronological /diary view of everything you've watched/read/played. This is Letterboxd's signature mechanic and the foundation the rest of this section builds on.

Evidence
No log/diary model exists. "Repeats" are computed via a Window annotation over history (app/models.py:334); there's no intentional re-log action and no diary route in any urls.py. _recent_activity reads history but isn't a browsable, dated journal.
Inspired by
Letterboxd diary, Backloggd journal, BGG play log
Sketch
New app/models.py: LogEntry(user, item, logged_on, rating, note, format, is_rewatch, source). A "Log again" action on the detail page + on cards. /diary grouped by month. Backfill: synthesize entries from existing simple_history on first view. Feed Wrapped from logs so rewatches finally count.
Effort
Large — new model + migration + views; but highest unlock value.
Net-new: IDEAS.md has "per-episode notes" and "soft-delete" but nothing resembling a diary/relog primitive. This is the keystone for A2–A5.

A2 Per-episode & per-season ratings/reviews Medium

Let users score and briefly review individual episodes (and write a whole-season review at a finale), the way Serializd and TV Time treat episodes/seasons as first-class objects.

Evidence
Episode (app/models.py:2005) has only end_date/item/related_season — no score, no notes. Seasons inherit score/notes but the UI never surfaces a "review this season" affordance.
Inspired by
Serializd, TV Time
Sketch
Add score+notes to Episode; tiny inline star row on the episode list; surface the existing Season.score/notes in a "Season review" card.
Effort
Medium
Net-new: IDEAS lists per-episode notes only — not ratings, and not season-level reviews.

A3 Reviews as objects w/ spoiler flag Low

Split a short, spoiler-taggable review from the freeform notes scratchpad, rendered with a blur-until-click spoiler guard. Makes "my reviews" exportable and Wrapped-able.

Evidence
Only one notes TextField on Media (app/models.py); no spoiler concept anywhere.
Inspired by
Letterboxd / Serializd reviews
Sketch
Reuse the A1 LogEntry.note + a has_spoilers bool; CSS blur reveal. No new model if A1 lands.
Effort
Small (free with A1)

A4 Format / edition per read Low

Record how you consumed something — audiobook vs print vs ebook; theatrical vs streaming; physical vs digital game. Powers "hours listened" stats and honest Wrapped breakdowns.

Evidence
No format/edition field on any media model. KOReader/Hardcover only know "a book."
Inspired by
Hardcover (audiobook-vs-print per read)
Sketch
LogEntry.format (TextChoices per media type) or a single format on Media; chip on detail + a Wrapped slice.
Effort
Small

A5 Play / session log for games & board games Medium

Generalize the existing vinyl Play model to board games (date, players, scores, win/loss) and games (a dated session of N minutes), then surface a BGG-style play count and H-index. Today only records can log a "play."

Evidence
Play/PlaySide exist only for Record (app/models.py:2214); board games & games just store a single progress integer. No session/play-count concept for them.
Inspired by
BoardGameGeek play logging + H-index; Backloggd calendar journal
Sketch
Extend Play (or A1 LogEntry) with optional players/scores JSON + duration_min; "Log a play" button on boardgame/game detail; play-count + H-index in statistics.py.
Effort
Medium
Net-new: not in IDEAS; the closest entry ("watch-with mode") is about partners, not play sessions/scores.

B "Decide what to watch / read next" beat decision paralysis

Yamtrack has passive nudges (Palate Cleanser surfaces one item; Watch Tonight ranks by taste) but no interactive "help me pick right now" tools — the category competitors invest in most heavily.

B1 Roulette / "Decide for me" High impact

A R-to-roll button that picks a random item from your Planning backlog, optionally filtered by media type / mood / runtime, with a satisfying reveal and "re-roll / log it" actions.

Evidence
_palate_cleanser (app/views.py:242) is a passive, single, server-chosen suggestion — there is no user-triggered random picker or filter-aware roll.
Inspired by
Letterboxd roulette (press R), Simkl random-from-filter
Sketch
New /roulette (or home widget) → BasicMedia.objects filtered to Planning + facets, .order_by('?')[:1]; Alpine card flip. Reuses existing mood filters.
Effort
Small — high delight per line of code.
Net-new: not in IDEAS at all.

B2 Time-budget picker ("I have 45 min") Medium

Tell the app how long you've got; it filters your in-progress/watchlist to things that fit — a 22-min episode, a 90-min film, a board game that plays in 30. Sofa & JustWatch lean on this hard.

Evidence
No runtime-aware filtering. media_list filters only status/sort/search/mood (app/views.py:616). Runtime metadata isn't stored on Item (Wrapped notes "video/game runtime deferred").
Inspired by
Sofa, JustWatch, BGG play-time
Sketch
Backfill Item.runtime from TMDB/IGDB/BGG on metadata fetch (mirrors the air_date backfill command), then a "time available" chip on home.
Effort
Medium — gated on the runtime backfill.

B3 Backlog analyzer Medium

"It will take ~340 hours / 12,000 pages to clear your Planning shelf." A forward-looking counterpart to the existing (past-facing) playtime stats, per media type.

Evidence
Stats are retrospective (get_game_stats, hours played). No "hours/pages remaining to clear backlog" anywhere.
Inspired by
HowLongToBeat Backlog Analyzer
Sketch
Sum runtime/page estimates over Planning items (HLTB import already gives game times; surface them). Panel on /statistics.
Effort
Medium (shares runtime backfill with B2)
Net-new: IDEAS has a "watch-time leaderboard" (past hours); a backlog projection is the inverse and absent.

B4 Surface HLTB "time to beat" on game pages Low

Show Main / Main+Extras / Completionist hour estimates on the game detail page so you can decide before starting — the single datapoint HLTB exists for.

Evidence
HLTB is an import source only (integrations/imports/hltb.py); the data isn't fetched/shown on the live game detail page.
Inspired by
HowLongToBeat
Sketch
Add a small HLTB lookup to the game detail context (cache 24h like other providers); three pills under the hero.
Effort
Small

C Lists, filtering & organization shape the library your way

Custom lists are manual, date-ordered bags of items. Power-trackers add dynamic/smart lists, manual ranking, favorites, and free-text tagging.

C1 Saved Smart Lists (rule-based) High impact

Lists that auto-populate from a saved filter ("In-progress anime rated 8+", "Planning films under 2h on a service I have"). Plex smart collections / Sofa smart lists / Maintainerr rules.

Evidence
CustomList is a static M2M of items (lists/models.py:48); filtering on media_list is ephemeral (status/sort/search/mood) and can't be saved or named.
Inspired by
Plex smart collections, Sofa, Maintainerr
Sketch
CustomList.is_smart + rules_json; resolve to a queryset at render. Reuse the existing filter machinery.
Effort
Large
Net-new: IDEAS has public/embed lists but no dynamic lists.

C2 Manual ranking & tier lists Medium

Drag to order a list into a ranked "My Top 25", or bucket items into S/A/B/C/D tiers — a hugely popular format in games/anime communities.

Evidence
CustomListItem has only date_added (lists/models.py:106) — no position/rank field, so manual ordering is impossible.
Inspired by
Backloggd ranked lists, community tier lists
Sketch
Add CustomListItem.position (+ optional tier char); SortableJS drag; new ListDetailSortChoices.MANUAL.
Effort
Medium

D Streaming-availability intelligence you already store the data

Yamtrack knows your region (watch_provider_region) and which services you pay for (streaming_providers) and uses them for the Watch-Tonight rail — but never proactively alerts you about availability changes.

D1 "Now streaming on your services" & "leaving soon" alerts High impact

When a Planning title newly lands on a service you subscribe to — or is about to leave one — push a notification (Apprise/Web Push, both already wired). The single most-loved JustWatch/Reelgood feature, and Yamtrack is one Celery task away from it.

Evidence
Notifications today are release/airing-only (events/notifications.py: send_releases, send_daily_digest). Watch-Tonight reads provider availability live (_available_providers_in_region, app/views.py:367) but nothing is diffed over time or alerted.
Inspired by
JustWatch availability/price alerts, Reelgood, Maintainerr "leaving soon"
Sketch
Nightly task: for each user's Planning movies/TV, fetch TMDB /watch/providers, store a per-item availability snapshot, diff vs last run → "now on Netflix" / "leaves Max in 5 days". Route through the existing notification + push delivery.
Effort
Medium — new periodic task + a small snapshot table; all delivery + provider plumbing already exists.
Net-new: not in IDEAS; "Where to watch" there was the static detail-page chip, not change alerts.

D2 "Filter to my services" across Browse & lists Low

A global toggle to hide anything you can't actually stream right now, applied to Browse and any movie/TV list — extends the Watch-Tonight logic everywhere.

Evidence
Provider filtering exists only inside the Watch-Tonight home rail; Browse (app/views.py:785) and lists have no "only my services" filter.
Inspired by
JustWatch "My Services", Letterboxd Pro service filter
Sketch
Reuse filter_providers + streaming_providers as an optional querystring/pref applied in Browse and media-list rendering.
Effort
Small

H Data quality & closing the loop richer, two-way data

H1 Content warnings / age-rating surface & filter Low

Show certification/age rating (and, where available, content advisories) on the detail page, and let Browse hide content above a threshold — useful for family/household accounts.

Evidence
Age ratings aren't surfaced or filterable. TMDB content-ratings & OMDB Rated are reachable (providers/tmdb.py, omdb.py) but unused for this.
Inspired by
StoryGraph content warnings; TV parental ratings
Sketch
Pull certification into metadata; chip on detail; a Browse "max rating" pref.
Effort
Small–Med

H2 Two-way scrobble-back to Trakt Medium

Books already round-trip via Hardcover; movies/TV/anime only flow in. Push your Yamtrack watches/ratings back out to Trakt so the rest of your ecosystem stays in sync.

Evidence
Trakt is import-only (integrations/imports/trakt.py); no outbound sync. Hardcover proves the pattern (integrations/signals.py echo-suppressed push).
Inspired by
Trakt scrobbler; Hardcover two-way (already in-house)
Sketch
Mirror the Hardcover outbound design: post_save on Movie/Episode → Trakt /sync/history, with last_trakt_sync_at echo suppression.
Effort
Large (but a well-trodden in-house pattern)
vs IDEAS: IDEAS has Letterboxd CSV export; this is live API push-back, distinct.

⚙ Methodology & sources

How this analysis was produced
  • Baseline: reset to latest main (0.25.2~ynh156) per the brief — 86 commits ahead of the prior branch — so the inventory reflects shipped reality, not the docs (which lag badly; CLAUDE.md predates music tracking, OPDS, the reading hub, etc.).
  • Codebase inventory: read every urls.py, the User preference model, app/models.py (media types, Media/Item/Episode/Record/Play), the home/statistics/detail views, integrations, events/notifications, and lists — to catalogue exactly what exists.
  • Competitor research: surveyed ~30 tools across all of Yamtrack's media categories — Trakt, Letterboxd, Serializd, TV Time, Simkl, JustWatch, Sofa, Reelgood, Goodreads, StoryGraph, Hardcover, BookWyrm, Oku, Backloggd, HowLongToBeat, GG, Grouvee, Playnite, AniList, MyAnimeList, Kitsu, AniChart, BoardGameGeek, Maintainerr, Overseerr/Jellyseerr, Ryot — and extracted their signature, named features.
  • Freshness filter: every candidate was cross-checked against (a) the shipped code and (b) the existing IDEAS.md queue/brainstorm/shipped sections. Anything already present or already proposed was dropped or explicitly differentiated (see the purple "vs IDEAS" notes).
  • Deliberately excluded as already-covered: bulk-select, duplicate/merge, public list pages, list embeds, friends/following, public read-only API, bookmarklet, soft-delete/trash, health page, swipe gestures, watch-with mode, home composer, per-episode notes, "already tracking" badge, OPDS (shipped), KOReader visibility (shipped), Letterboxd CSV, OL next-in-series, numeric goal ring, "did you finish" nudge, rating-quirks dashboard, per-genre heatmaps.

Social/community features from competitors (live activity feeds, federation, buddy reads, clubs, comments, GeekBuddy) were largely set aside: they presuppose a multi-tenant social graph that runs against Yamtrack's self-hosted, single-tenant grain, and IDEAS already tracks a minimal "friends/following" idea. The gaps above are intentionally things that work for a solo self-hoster.
